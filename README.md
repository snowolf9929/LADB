# LADB

一个适用于 Android 的本地 ADB Shell！

# 关于本 Fork

这是 [tytydraco/LADB](https://github.com/tytydraco/LADB) 的一个 Fork。应用的使用方式与原版完全相同，改动如下：

- 移除了许可证校验、Google Play Services 依赖以及未使用的权限
- 在原有英文之外新增了俄语翻译，包括 Shell 输出内容
- 应用内可切换语言；在 Android 13 及更高版本上会跟随系统的应用语言设置
- Material 3 界面：Android 12 及以上支持动态取色，Android 13 及以上支持主题图标
- 目标版本为 Android 17，包含端口发现所需的本地网络权限
- 用当前 API 替换了已废弃的平台 API，行为保持一致，向下兼容至 Android 8
- 更可靠的首连体验：端口发现会等待端口就绪，连接结果会校验并自动重试
- 在无线调试设置中，配对名称显示为 LADB
- 发布版构建会移除日志
- 由 GitHub Actions 使用本仓库中的密钥，为每种 ABI 生成签名构建，另有通用（universal）版本
- 新增远程设备支持：可以用手机 A 通过无线调试直接调试同一网络下的手机 B，配对记录会保存在应用私有目录，第二次连接无需再输入配对码

# 工作原理

LADB 将 ADB 服务器打包在应用库中。通常，这种服务器无法连接本机设备，因为需要有效的 USB 连接。而 Android 的无线调试（Wireless ADB Debugging）功能可以让服务器与客户端在本机进行通信。

# 首次设置

请将 LADB 和系统设置同时打开，使用分屏或悬浮窗模式。因为一旦对话框被关闭，Android 会使配对信息失效。添加一个无线调试连接，然后把配对码和端口复制到 LADB 中。请保持两个窗口都打开，直到设置中的对话框自行关闭。


# 远程调试其他手机

除本机之外，LADB 还能连接同一局域网内另一台开启了「无线调试」的手机（Android 11 及以上），全程不需要电脑。

## 首次连接（需要配对一次）

1. 在**目标手机**上打开 设置 → 开发者选项 → 无线调试，保持开启；
2. 点「使用配对码配对设备」，记下弹出的 **IP 地址、配对端口、6 位配对码**；
3. 在**本机** LADB 顶部的设备栏点 ＋（添加远程设备），填入名称（可选）、IP 地址、配对端口、配对码；
   - 「连接端口」可以留空，LADB 会通过 mDNS 自动发现；也可以直接填写目标手机「无线调试」页面顶部显示的端口；
4. 点「配对并连接」。目标手机可能弹出「允许 USB 调试吗？」，在目标手机上点一次「允许」（可勾选「始终允许」）。

## 之后的连接（无需配对码）

配对成功后，配对信息保存在 LADB 的应用私有目录中：

- `files/.android/adbkey`、`adbkey.pub`：本机的 ADB 密钥，也是「配对记录」的核心；
- `files/.android/adb_known_hosts*`：配对时记下的目标主机密钥；
- 设备列表（IP、别名、上次使用的端口）保存在应用设置里。

所以**第二次连接只需要**：打开 LADB → 点顶部设备栏 → 选中该设备 → 点「连接」。

> 注意：无线调试每次关闭再打开都会分配**新的连接端口**，端口并不固定。LADB 会优先通过 mDNS 自动发现新端口；如果没发现，可以在设备菜单（⋮）里用「连接端口」手动填写目标手机当前显示的端口。

## 说明与限制

- 两台手机必须在同一局域网内（同一 Wi-Fi，或目标手机开热点、本机连上去）；
- 连接本机不需要确认，连接远程设备时目标手机会弹出授权框，必须由对方点一次「允许」；
- LADB 自身的 ADB 服务器仍然只监听本机 `127.0.0.1:5037`，局域网内其他设备无法连接；
- 「设备菜单 → 忘记设备」「设置 → 取消配对」「设置 → 重置配对密钥」可以清除配对记录，其中重置密钥会删除 ADB 密钥文件，所有设备（包括本机）都需要重新配对。

# 已知问题

遗憾的是，LADB 目前与 Shizuku 不兼容。也就是说，如果安装了 Shizuku，LADB 通常无法正常连接。要使用 LADB，必须先卸载 Shizuku 并重启手机。

# 疑难解答

大多数错误都可以通过以下方式解决：清除 LADB 的应用数据、删除设置中的所有无线调试连接，然后重启。

# 许可证

许可证基本是宽松的，唯一限制是不允许将非官方构建发布到 Google Play 商店。

# 隐私政策

LADB 不会将任何设备数据发送到应用之外。我们不会收集或处理您的数据。
